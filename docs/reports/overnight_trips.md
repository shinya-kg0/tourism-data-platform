# 宿泊旅行統計調査データ整備 作業レポート

作成日：2026年11月3日

## エグゼクティブサマリ

- **目的**：観光庁「宿泊旅行統計調査」の直近10年分（2016〜2025年、年確定値）を、Pythonで分析できる形にそろえること。
- **結論**：10年分・21表・全月のデータを、表ごとに1ファイルの縦持ちCSVにまとめた。年・月・地域・区分を指定するだけで集計できる。
- **e-Stat APIだけでは足りなかった**：APIで取れるのは2016年の年確定値だけ（2019年3月の更新が最後）。一方、e-StatのExcelは2016〜2025年がそろっていたため、取得元をExcelに一本化した。
- **Excelの形式の違いを吸収した**：2016〜2019年は旧形式（結合セル・注記付き・単位の行なし）、2020年以降は新形式。旧形式の年には新形式の見出しを列の位置で当てはめた。全表で列の数と並び順が同じことを確認している。
- **値の正しさを確かめた**：2016年の国籍別の表は、照合できた13,542セルがすべてAPIの値と一致した。年計と月別合計の差は丸めによる±10人泊だけ。
- **主な結果**：延べ宿泊者数は2025年に6億6,111万人泊で過去最多。外国人の比率は2016年の14.1％から27.2％まで上がった。
- **使うときの注意**：2020〜2022年はコロナの影響で大きく落ち込んでいる。国籍別の表は従業者数10人以上の施設だけの集計なので、全体の表と合計が合わない。

## 1. 背景と目的

[訪日外国人消費動向調査の作業](consumer_behavior_survey.md)に続き、宿泊旅行統計調査の過去10年分を分析できる形で用意した。消費動向調査では表をシートごとにCSVへ変えるだけだったが、今回はすぐ集計できるよう、全表を縦持ちの形に変換した。

## 2. データの所在の調査結果

| 取得方法 | 対象期間 | 内容 |
|---|---|---|
| e-Stat API（統計表データ） | 2016年（年次・月次） | 32表。2019年3月の更新が最後 |
| e-Statのファイル（Excel） | 2007〜2025年（年確定値） | 1年1ファイル。2016〜2025年はすべて `.xlsx` |

**Excelを使うことにした理由**：APIで取れるのは10年のうち1年分だけだった。またExcelとAPIでは表の形が違う。消費動向調査で課題として残した「取得元の一本化」を、今回は最初から行った。

### Excelの構成

1年あたり約270シートで、どの年も表の構成は同じ。

| 区分 | 表 | 内容 |
|---|---|---|
| 本表 | 第1表 | 施設数（従業者数・宿泊目的割合別、宿泊施設タイプ別） |
| | 第2・3表 | 延べ宿泊者数・実宿泊者数（従業者数・宿泊目的割合別。外国人の内訳あり） |
| | 第4・5表 | 延べ宿泊者数・実宿泊者数（宿泊施設タイプ別。外国人の内訳あり） |
| | 第6〜8表 | 定員稼働率・利用客室数・客室稼働率 |
| | 第9・10表 | 居住地（県内・県外）別の延べ宿泊者数 |
| 国籍別推計 | 参考第1表 | 国籍（出身地）21区分別の外国人延べ宿泊者数 |
| 10人以上施設 | 参考第2〜11表 | 従業者数10人以上の施設だけで集計した第1〜10表 |

各表に年計と1〜12月のシートがある（第1表・参考第2表は月別のみ）。地域は全国・47都道府県・10運輸局等の58区分。

### 年による形式の違い

| 年 | 形式 | 特徴 |
|---|---|---|
| 2016〜2019 | 旧形式 | 見出しが結合セル、注記（「1)」）や改行が入る、単位の行がない、2016年は地域コードがない |
| 2020〜2025 | 新形式 | 見出しが「グループ / 区分 / 項目 / 単位」の4段で、セルごとに値が入っている |

## 3. 実施内容

### 3.1 取得と変換（`fetch_overnight_trips.py`）

- e-Statから10年分のExcelをダウンロードする。ダウンロード済みのファイルは取り直さない。
- 全シートを縦持ちに変換し、表ごとに全年・全月を1つのCSVにまとめる。
- 新しい年から順に読み、新形式の見出しを覚えておく。旧形式の年は、同じシート名の新形式の見出しを列の位置で当てはめる。列の数が合わない場合はエラーで止める。
- 表記の揺れをそろえた。
  - 全国の行の名前（「施設所在地計」「令和7年4月」「平成28年 1～12月 計」など）は「全国」にそろえた。
  - 2016年は地域コードがないので、ほかの年の地域名からコードを補った。
  - 値に付いた記号（`*20,520` など）は、数値と記号に分けた。
- 見出しが「うち外国人〜」の列から右は、`target` 列を「外国人」にした。全体と外国人を区別するためである。

```
.venv/bin/python fetch_overnight_trips.py            # 全年（約1分半）
.venv/bin/python fetch_overnight_trips.py 2024 2025  # 指定した年だけ取り直す（CSVは全年分で作り直す）
```

### 3.2 出力するCSVの形

| 列 | 内容 | 例 |
|---|---|---|
| year | 年 | 2025 |
| month | 月（0＝年計） | 0, 1〜12 |
| area_code / area | 都道府県コード・名前（全国・運輸局はコードなし） | 13 / 東京都 |
| target | 全体 / 外国人 | 外国人 |
| group / sub / item | 見出し（3段） | 従業者数（4区分）、宿泊目的割合（2区分） / 0～9人 / 観光目的の宿泊者が50％以上 |
| unit | 単位 | 人泊、施設、室、％ |
| value | 値 | 179922130 |
| flag | 記号 | `-`＝該当なし、`*`＝標準誤差率30％以上 |

### 3.3 ノートブック（`statistical_survey_on_overnight_trips.ipynb`）

- CSVがなければスクリプトを実行して作る。
- 表の一覧（目次）を表示し、`load("第2表")` で読み込めるようにした。
- 集計の例として、次の5つを入れた。全国の延べ宿泊者数（日本人・外国人）、施設タイプ別の客室稼働率、国籍別の外国人延べ宿泊者数、都道府県別の外国人延べ宿泊者数、月別の延べ宿泊者数。

## 4. 検証

| 確認したこと | 結果 |
|---|---|
| 2016年の国籍別の表（参考第1表）とAPIを全セルで照合 | 照合できた13,542セルがすべて一致した。照合できなかったのは運輸局の行だけで、APIでは「運輸局等（再掲）_」が付くなど名前の付け方が違うため |
| 2016年の全国の延べ宿泊者数とAPI | どちらも492,485,160人泊で一致した |
| 年計と月別合計 | どの年も差は±10人泊以内。公表値が10単位で丸められているため |
| 旧形式と新形式の列の対応 | 全21表で列の数が一致した。見出しの違いは、旧形式で「計」が注記だけになっている列だけ |
| 地域の区分 | どの年も58区分で同じ |
| 値の欠け | 空の値にはすべて記号（`-` か `*`）が付いており、理由の分からない欠けはない |

**読み取れること**

## 6. 使うときの注意

1. **国籍別の表は全体の表と合計が合わない。** 参考第1表は従業者数10人以上の施設だけの推計で、第2表の外国人延べ宿泊者数より小さい（2016年は6,407万人泊と6,939万人泊）。
2. **`*` の付いた値は誤差が大きい。** 参考第1表で `*` の付いた値は標準誤差率が30％以上ある。都道府県×国籍のように細かく分けて見るときは特に注意する。
3. **地域の行には再掲が含まれる。** 運輸局等の行は都道府県の合計を載せ直したものなので、都道府県と運輸局を足すと二重に数えてしまう。都道府県だけを使うときは `area_code` が入っている行に絞る。
4. **旧形式の見出しは新形式から当てはめたもの。** 2016〜2019年の見出しは2025年の見出しを位置で当てはめている。2016年は全セルで確かめたが、2017〜2019年は列の対応だけを確かめた。
5. **CSVは合わせて約300MBある。** 毎回全部を読まず、必要な表だけ `load()` で読む。

## 8. 今後の課題

- 訪日外国人消費動向調査と組み合わせる。たとえば国籍別の宿泊者数×1人当たり消費単価から消費額を推計する、都道府県別の訪問率と宿泊者数を比べる、など。
- 運輸局の行など、APIとの照合で使わなかった名前の付け方の違いを、必要に応じてそろえる。
- 2026年の年確定値が公表されたら、`FILES` に統計表ファイルIDを追加して取り込む。
- CSVが大きいため、分析が増えてきたらParquet形式での保存を検討する。
